# Requirements — Velocity Dashboard

作成者: Product Owner Agent
最終更新: 2026-06-03

## ターゲットユーザー

| ペルソナ | 主な利用シーン | Jira での痛み |
|---------|--------------|--------------|
| **エンジニア（実装者）** | 朝の自分のタスク確認、コード書き始め | 自分のチケット一覧に辿り着くのに 3 クリック以上、見やすさが悪い |
| **チームリード / スクラムマスター** | 朝会前のスプリント状況把握、メンバー負荷確認 | 「誰が overload？」がワンクリックで分からない |
| **PM / マネージャー** | 週次レポート、エピック進捗追跡 | KPI を組み立てるのにダッシュボードのカスタマイズが必要 |

ペルソナは 3 つだが、**全員が共通で経験する痛み**を優先する。個別ペルソナの専用機能はそれが共通体験を犠牲にするなら却下。

## Jira を超えるための 5 つのジョブ

各ジョブは [Jira での所要操作] と [当ダッシュボードの目標] を併記する。

### J1: 自分の今日やるべきチケットを把握する

| | Jira | 目標 |
|--|------|------|
| 所要クリック | 3-4（ボード → フィルタ → 自分 → 並び替え） | **0**（ホーム画面に既に出ている） |
| 所要時間 | 10-15 秒 | **3 秒以内** |

**Acceptance**: ダッシュボード起動 → 上部 KPI と並んで「あなたの今日のタスク」セクションが見える。並びは In Progress > Review > To Do の優先度順。

### J2: 重要度の高い停滞チケットを発見する

| | Jira | 目標 |
|--|------|------|
| 所要クリック | 5-8（フィルタ作成 → 保存 → 適用 → ソート） | **1**（フィルタ／ハイライト切替） |
| 検出ロジック | 手動でクエリを組む | 自動（更新無し N 日 + 高優先度） |

**Acceptance**: 「⚠ 停滞中」バッジが、3 日以上ステータス変化のない High/Critical 優先度のチケットに自動付与される。フィルタで停滞のみ表示できる。

### J3: スプリントの今日の進捗を一目で把握する

| | Jira | 目標 |
|--|------|------|
| 所要画面遷移 | 2-3（ボード → バーンダウン → 戻る） | **0**（既に同じ画面に出ている） |
| 情報密度 | KPI と図が別画面 | KPI / バーンダウン / 担当者負荷を 1 画面に |

**Acceptance**: 「サマリ」タブで KPI + バーンダウン + 担当者別パフォーマンス + 直近 6 スプリントの Velocity が縦スクロール内に収まる（PC 1920×1080 で）。

### J4: チームの誰が overload しているか即座に判断する

| | Jira | 目標 |
|--|------|------|
| 所要操作 | レポート機能を開く（数クリック + 設定） | **0**（サマリに常時表示） |

**Acceptance**:
- 担当者別パフォーマンステーブルがサマリタブに常時表示される
- 担当者 1 人あたりの「未完了 pt」「In Progress 件数」が見える
- 平均より 1.5σ 以上多い担当者は色（例: orange ハイライト）で示される

### J5: チケットを階層付きでカレンダー（ガント）として把握する

| | Jira | 目標 |
|--|------|------|
| 機能の有無 | Advanced Roadmaps は別契約・別画面 | **同じアプリの 1 タブ** |
| 階層編集 | フォームで手動指定 | **ドラッグ&ドロップ** |

**Acceptance** (既に概ね実装済):
- プロジェクト全体のガントが 1 画面に
- 子チケットの並び順を DnD で変更
- 親子関係の付与と解除を DnD で

## 非機能要件

| 項目 | 目標 | 測定方法 |
|------|------|---------|
| 初回描画 | 1 秒以内（cache warm） | Lighthouse / Performance API |
| タブ切替 | 100ms 以内 | DevTools Performance |
| フィルタ反映 | 即時（同期計算） | 体感、React Profiler |
| 楽観的更新 | 全 mutation | コードレビュー |
| キーボード操作 | 主要操作にショートカット | UX Agent レビュー |

## 明示的に「やらない」

| やらない | 理由 |
|----------|------|
| Jira への双方向書き戻し | スコープ外。当初の目的は閲覧と分析。 |
| ワークフローのカスタマイズ | Jira の役割。同じ機能で勝つ必要なし。 |
| 通知（メール / Slack） | OS 通知や他ツールの仕事。Jira もこれで負けている。 |
| Wiki / コンフルエンス機能 | スコープ外。 |
| モバイルアプリ | レスポンシブで十分。アプリ化は ROI 不明。 |

## 優先順位

1. **F-009 (自分のタスク)** - J1 を完了するためにマスト
2. **F-011 (overload 自動検出)** - J4、サマリの説得力が上がる
3. **F-010 (停滞検出)** - J2、データ依存度が高いので Data Analyst Agent と協調
4. **F-012 (キーボード)** - 体感速度が劇的に上がる
5. **F-014 (TanStack Query)** - スケール時の体感速度に効く

詳細な ROI 評価は AI PM Agent → `docs/feature_proposals.md` を参照。

## 2. 重大な UX 問題（要修正）

### 🔴 #1: 起動 → 「自分の今日のタスク」までの導線がない

**症状**: ダッシュボードを開くと **全員のサマリ**が出る。自分のタスクを見るには:
1. 課題管理タブをクリック
2. フィルタの担当者プルダウンを開く
3. 自分の名前を選択
4. ステータスフィルタを「In Progress」に
5. ソートを「優先度」に変更

**5 クリック**。Jira のマイ・ボードと同等で、勝てていない。

**推奨**: サマリタブの **最上部** に「あなたの今日のタスク」セクションを置く（F-009）。

```
┌──────────────────────────────────────────────┐
│ 👤 あなたの今日のタスク                          │
│   ・ECOM-1234  ⚠停滞2日 ログイン画面実装 (In Progress)│
│   ・ECOM-1255  カート API 修正 (Review)         │
│   ・ECOM-1278  検索バグ調査 (To Do)             │
└──────────────────────────────────────────────┘
[ KPI カード ... ]
```

担当者は「現在ログイン中の email」から判定。一致しなければ折りたたんで非表示。

### 🔴 #2: スプリントタブが画面の半分を占める

**症状**: `src/components/Dashboard.tsx` line 511-548

スプリントが 6 個並ぶと、画面上部にボタン列が二段になる。さらにフィルタバーがあるため、コンテンツが始まるのは縦スクロールの **240px** 下から。

**推奨**:
- アクティブスプリントは大きく、完了スプリントは小さく折りたたみアコーディオン化
- またはセレクトボックス + 「< 前 / 次 >」矢印にする

```
[ Sprint 24 ▼ ] [ < 前 ] [ 次 > ]   完了スプリントを含める □
```

または:

```
🟢 Sprint 24 (active)  ✓ S23  ✓ S22  ✓ S21  ...
```

### 🔴 #3: フィルタバーが「使えそう」だが「使い方が伝わらない」

**症状**: `src/components/FiltersBar.tsx`

4 つのプルダウンが横に並んでいる。フィルタリングが効いている / 効いていない状態の視覚差が弱い。「クリア」ボタンも目立たない。

**推奨**:
- フィルタが 1 つでも適用中: フィルタバーの **背景色を変える**（例: blue-900/30）
- フィルタチップ化: 「担当者: 田中 ×」のようにバッジ表示
- グローバル `/` キーで検索フィールドにフォーカス

### 🟠 #4: 「停滞しているチケット」が一目で分からない

**症状**: 課題管理タブの全課題一覧では、ステータスは見えるが「動いていない」期間は見えない。

**推奨**:
- 各課題の **最終更新日**をカラムに加える
- 「停滞 N 日」バッジを自動付与（status が `In Progress` または `Review` で N 日変化なし）
- バッジは Critical/High 優先度のみ目立たせる（情報過多防止）

### 🟠 #5: 「誰が overload か」がサマリで判断できない

**症状**: 担当者別パフォーマンステーブル（サマリタブ）は **過去実績** を見せている。今この瞬間誰が抱えているかが不明。

**推奨**:
- 担当者別に **未完了 pt と In Progress 件数** をテーブル列に追加
- 平均 + 1.5σ を超える担当者は orange ハイライト
- 5 件以上 In Progress を抱える担当者は red ハイライト

## 3. 中程度の問題

### 🟡 #6: グローバル検索が無い

検索はフィルタバーの中の入力欄に限定されている。スプリントを跨いで「あの ECOM-1234 のチケット」を探したい時、まず該当スプリントを当てる必要がある。

**推奨**: `Cmd+K` / `Ctrl+K` でグローバル検索パレット（全スプリント横断、ID / タイトル / 担当者）。

### 🟡 #7: チケットの URL（パーマリンク）が無い

**症状**: 「ECOM-1234 を確認して」と Slack で送られても、ダッシュボードでは URL 共有できない。

**推奨**: `#/issue/ECOM-1234` 形式のハッシュルーティング。深リンク経由なら起動時に該当チケットの編集モーダルを開く。

### 🟡 #8: ガントの今日線が画面外になりやすい

**症状**: プロジェクト全体表示の場合、過去 12 週分が画面に乗らない。横スクロールが必要。今日の位置が分からない。

**推奨**: 起動時に「今日」を中心に表示するようスクロール位置を初期化。あるいは「📍 今日に移動」ボタン。

### 🟡 #9: 編集モーダルが大きすぎる

**症状**: `src/components/IssueEditModal.tsx`

ID / タイトル / ステータス / 担当者 / Points / 見積 / 実績 / タイプ / 優先度 / 着手日 / 期限 / エピック / 親 / ラベル … と縦に長い。スクロールしないと「保存」ボタンに届かないことがある。

**推奨**:
- 必須フィールドのみ表示、それ以外は「詳細を表示 ▼」で展開
- もしくは右サイドパネル化（モーダル全画面オーバーレイより視認性が高い）

### 🟡 #10: ワークログ一覧の役割が不明確

**症状**: 課題管理タブの下部に独立して存在するが、誰が何のために見るのかが弱い。

**推奨**: 削除候補、または「自分のワークログだけ」「今週分だけ」のような時間軸フィルタ付きに。

## 4. 軽微な点

- 🔵 #11: ステータスの色（Done=emerald, Review=purple）が直感と異なる。Review=yellow/orange のほうが「待ち」のニュアンスが伝わる。
- 🔵 #12: KPI カードの数値フォントは大きくて良い。一方で「pt」「件」のラベルが小さすぎる。
- 🟢 #13: モーダルを Esc で閉じられない。
- 🟢 #14: フィルタクリアボタンが右端にあるが、フィルタ自体は左から並ぶ。スキャンの動線と逆。
- 🟡 #15: ダブルクリックでスプリント編集モーダルが開くが、これは発見不能な操作。明示的な「編集」アイコンが必要。

## 5. 拒否した提案（記録）

このセクションは UX Agent が拒否権を行使した記録です。今後、他のエージェントや人間がここに挙げた機能を再提案する場合、別の正当化が必要です。

### ❌ チケットへのコメント機能
**理由**: Jira の役割。当ダッシュボードでチケットを編集する想定だが、議論はその場でクローズしたい。コメント機能を入れるとそこに議論が散乱し、Jira との二重管理になる。
**代替**: チケット詳細から Jira へのリンクを 1 クリックで飛べるようにする。

### ❌ 通知（メール / Slack 連携）
**理由**: J5 ジョブの「Jira より速い」原則から外れる。これはバックグラウンド機能であり、ダッシュボード起動時の体験には寄与しない。Jira もこの機能で勝負していない。
**代替**: 「停滞バッジ」のような視覚的シグナルで代替（受動通知ではなく能動把握）。

### ❌ チャート種類のカスタマイズ（ピボット的に切り替え）
**理由**: 「サマリで全部見せる」の方向と矛盾。選択肢が増えると判断時間が増え、ジョブの所要時間が伸びる。
**代替**: 必要なら専用タブを新設する。サマリは「決め打ち」のままが速い。

### ❌ コメント・メンション機能
**理由**: 上記コメント機能と同じ。

### ❌ 任意のフィルタ条件を保存
**理由**: フィルタ保存は Jira の負け筋。保存したフィルタが多すぎて結局探すのに時間がかかる。代わりに「3 日以上停滞 + High」のようなプリセットをハードコードで提供したほうが早い。
**代替**: F-010（停滞検出）のように、価値の高いフィルタを既製として提供。

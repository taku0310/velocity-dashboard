## 採用 #1: あなたの今日のタスクセクション

**問題（証跡）**
- `requirements.md` J1: 起動 → 自分のタスク確認まで 5 クリック必要（Jira と同等で勝てていない）
- `ux_review.md` #1 (🔴): 重大な UX 問題として既に特定

**提案**
サマリタブの最上部に折りたたみ可能な「あなたの今日のタスク」カードを配置。

```
┌─────────────────────────────────────────────────────┐
│ 👤 田中 太郎 さんの今日のタスク (3 件)         [折りたたむ ▼] │
├─────────────────────────────────────────────────────┤
│ 🔵 ECOM-1234  ログイン画面実装          In Progress │
│    ⚠ 停滞 2 日                                       │
│ 🟣 ECOM-1255  カート API レビュー        Review     │
│ ⚪ ECOM-1278  検索バグ調査              To Do      │
└─────────────────────────────────────────────────────┘
```

**現在ログイン中の担当者の特定**
- Jira 認証時の `email` から `assignee.displayName` を逆引き
- マッチしなければカード自体を非表示
- モックモードでは「未設定」状態。プルダウンで「私は誰？」を選択（localStorage 保存）

**ROI 試算**
- 起動毎に 5 クリック × 1.5 秒 / クリック = 7.5 秒節約
- 1 日 3 回起動として 22.5 秒 / 日 × 5 日 = **約 2 分 / 週**
- 実装: 0.5 日（カードコンポーネント + ログインユーザー紐付け + localStorage）
- **ROI = 2 ÷ 0.5 = 4**（基準 5 には届かないが、J1 を完了するためマスト）

**実装コスト詳細**
- `src/components/MyTasksCard.tsx` 新規（80 行程度）
- `Dashboard.tsx` のサマリタブ先頭に挿入（5 行）
- ログインユーザー特定ロジック: useJiraAuth に `currentUserDisplayName` 追加 OR モック用に localStorage キー追加

**依存・前提**
- なし。即着手可能

**Unlock するもの**
- F-011 担当者 overload 検出（同じユーザー特定ロジックを共有）
- F-010 停滞検出（同じ停滞バッジコンポーネントを共有）
- パーソナライゼーション基盤（将来の「自分の Velocity」「自分の見積精度」へ）

**トレードオフ**
- ⚠ サマリ画面の縦長さが増す。スプリントタブ圧縮（UX #2）と組み合わせて吸収。
- ⚠ モックモードで「私は誰？」を選ばないと出ない。初回 onboarding が必要。

## 採用 #2: 停滞チケット自動検出 + 担当者 overload ハイライト

**まとめて 1 機能として実装する**理由: 両方とも「色を付ける」「バッジを出す」だけの軽い変更で、データソースは同じ（dataset hook + Date 計算）。

**問題（証跡）**
- `requirements.md` J2 / J4: Jira では発見できない
- `ux_review.md` #4 / #5 (🟠 / 🔴): 既に特定済み
- 直近の Mock データでも、停滞しているように見える In Progress チケットが目視で発見しづらい

**提案**

### A. 停滞チケットバッジ

ステータスが `In Progress` または `Review` で **N 日**動いていないチケットに `⚠ 停滞 N 日` バッジを自動付与。

「動いていない」の判定:
- v1: `completionDate` も `worklogs` も 3 日以内に更新されていない
- 将来: Jira のステータス変更履歴を見る（バックエンド経由）

表示先:
- 全課題テーブル
- Kanban カード
- ガント行
- 「あなたの今日のタスク」カード内

色:
- 3-5 日: yellow (`text-yellow-300`)
- 6-10 日: orange (`text-orange-300`)
- 11+ 日: red (`text-red-300`)

### B. 担当者 overload ハイライト

担当者別パフォーマンステーブルに 2 列追加:
- **進行中 (件)**: その担当者の `In Progress` 件数
- **未完了 pt**: 同担当者の `To Do` + `In Progress` + `Review` の合計 pt

しきい値:
- In Progress が 5 件以上 → 行を `bg-red-900/20`
- 未完了 pt が平均 + 1.5σ 以上 → 行を `bg-orange-900/20`

ヘッダーに凡例: 「🟠 平均超過　🔴 同時進行 5 件以上」

**ROI 試算**
- スプリント中の「あれどうなってる？」を聞く回数を 1 人あたり週 1 回減らす → 5 分 / 週
- チームリードの朝会前準備を週 1 回 5 分削減 → さらに 5 分 / 週
- 合計 **10 分 / 週**
- 実装: 1 日（バッジコンポーネント、しきい値計算、テーブル列追加）
- **ROI = 10 ÷ 1 = 10**

**実装コスト詳細**
- `src/utils/staleness.ts` 新規（停滞日数計算、20 行）
- `src/components/StalenessBadge.tsx` 新規（20 行）
- `src/utils/dataCalculations.ts` 拡張（overload しきい値計算）
- `src/components/AssigneeTable.tsx` に 2 列追加 + 行色分け
- 表示先 4 箇所（Issues, Kanban, Gantt, MyTasks）でバッジ使用

**依存・前提**
- なし。データは既に `dataset` にある。

**トレードオフ**
- ⚠ 「3 日」のしきい値はデフォルト。設定で変更可能にする？ → **しない**。設定肥大化は Jira の負け筋。
- ⚠ 停滞判定が `worklogs` 依存だが、worklogs が無いチケットもある。 → 第 2 階層フォールバック: `dueDate` が過ぎていれば停滞扱い。

## 採用 #3: フィルタバー視認性改善 + Cmd+K グローバル検索

**まとめて 1 機能として実装する**理由: 両方とも「課題に早く辿り着く」ジョブ。実装パターン（コマンドパレット風 UI）を共有する。

**問題（証跡）**
- `ux_review.md` #3 (🔴): フィルタ適用中の視認性が低い
- `ux_review.md` #6 (🟡): グローバル検索が無い、スプリント横断検索ができない

**提案**

### A. フィルタバー強化

- フィルタが 1 つでも適用中: バー全体が `bg-blue-900/20`
- 適用中のフィルタを **削除可能なチップ** で表示

```
🔍 [_______]  状態: ▼  担当者: ▼  ラベル: ▼     [ ✕ クリア ]

▼ フィルタ適用中（背景青）:
[担当者: 田中 ×] [ラベル: api ×]     [ ✕ クリア (2)]
```

- `/` キーで検索フィールドにフォーカス

### B. Cmd+K グローバル検索パレット

- `Cmd+K` / `Ctrl+K` でモーダル風パレットが開く
- 全スプリント横断で ID / タイトル / 担当者を検索
- 結果リストは矢印キーで選択、Enter で該当チケットの編集モーダルを開く
- カテゴリ別: 「課題」「エピック」「スプリント」（将来）

```
┌────────────────────────────────────────────┐
│ 🔍 ECOM-                                    │
├────────────────────────────────────────────┤
│ 課題                                         │
│   ECOM-1234  ログイン画面実装  Sprint 24    │
│   ECOM-1255  カート API       Sprint 24    │
│   ECOM-1278  検索バグ調査     Sprint 23    │
├────────────────────────────────────────────┤
│ ↑↓ 移動  Enter 開く  Esc 閉じる              │
└────────────────────────────────────────────┘
```

**ROI 試算**
- Slack で「あの ECOM-XXX」を探すケース、週 3 回 × 30 秒 = **1.5 分 / 週**
- フィルタ適用ミス（「あれ？ フィルタ効いてた？」）の混乱解消、週 2 分節約
- 合計 **3.5 分 / 週**
- 実装: 0.5 日
- **ROI = 3.5 ÷ 0.5 = 7**

**実装コスト詳細**
- `src/components/CommandPalette.tsx` 新規（100 行程度、cmdk ライブラリ検討）
- `src/components/FiltersBar.tsx` 改修（チップ化）
- `src/hooks/useKeyboardShortcuts.ts` 新規（`/`, `Cmd+K`, `Esc` 処理）

**依存・前提**
- ライブラリ追加検討: [`cmdk`](https://cmdk.paco.me/)（300 行・MIT）か、自前実装
- 自前実装でも 1 日以内で書ける

**トレードオフ**
- ⚠ `Cmd+K` は VSCode / Slack / GitHub 等でも使われる。ブラウザの拡張アドオンと競合する可能性あり。 → エスケープしやすいので問題なし。

| 1 | あなたの今日のタスク | 4 | 第 1 sprint |

- 同上。現状 React state + localStorage で動いている

- 現状の情報密度は既に Jira を超えている
- 「あなたの今日のタスク」追加で十分

- スコープ外（requirements.md で明示済み）

### ❌ ピボットテーブル機能
